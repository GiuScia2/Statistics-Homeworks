From Wallet Seed to Ethereum Address

Hashing, Key Derivation and Cryptographic Primitives

An exploration of the cryptographic standards behind Ethereum wallets, from mnemonic phrases to checksummed addresses, including statistical properties.

01 / INTRODUCTION

Understanding Ethereum Wallets

From human-readable recovery words to cryptographic keys and Ethereum addresses.

Introduction and Objectives

Modern cryptocurrency wallets rely on multiple cryptographic standards to manage secret keys and generate blockchain addresses. Rather than storing an unrelated private key for every account, hierarchical deterministic wallets can derive many keys from a single initial seed.

This homework explores the complete process of deriving an Ethereum address from a BIP-39 mnemonic phrase. The demonstration connects key derivation, elliptic-curve cryptography, cryptographic hashing and address checksum encoding.

Particular attention is given to the distinction between generating secret material, deriving keys, calculating public keys, hashing data and encoding addresses. These operations use different mathematical techniques and serve different purposes.

Experimental Approach

The interactive demonstration uses a public BIP-39 test mnemonic and the test passphrase TREZOR. All results are deterministic and can be checked against reference values.

The wallet derivation is implemented using the browser Web Crypto API and ethers.js. A separate statistical experiment examines the avalanche behavior of Keccak-256 by modifying one input bit at a time.

The historical timeline and technical discussion place these operations within the broader development of cryptographic standards.

This is an educational experiment using publicly known test credentials. The displayed secret keys must never be used to hold real cryptocurrency. Never enter a real wallet recovery phrase into this page.

03 / CRYPTOGRAPHIC STANDARDS

Standards and Primitives

Understanding the standards and cryptographic operations behind Ethereum wallet derivation.

Technologies Behind the Pipeline

Ethereum wallet derivation combines several standards and cryptographic primitives. Each component has a specific purpose, from representing secret information to deriving keys and generating addresses.

MNEMONIC & SEED

BIP-39

BIP-39 represents random entropy and checksum bits as a mnemonic phrase. The mnemonic and an optional passphrase are processed using PBKDF2-HMAC-SHA512 with 2048 iterations.

The result is a deterministic 512-bit seed used to initialize the wallet.

HD KEY DERIVATION

BIP-32

BIP-32 defines hierarchical deterministic wallets, allowing many related keys to be derived from a single seed.

HMAC-SHA512 generates the master private key and a 256-bit chain code. Child keys can then be derived through hardened or non-hardened derivation.

WALLET ORGANIZATION

BIP-44

BIP-44 defines a standard hierarchy for organizing derived wallet keys. Our Ethereum example uses:

m/44'/60'/0'/0/0

The value 60 identifies Ethereum. The apostrophe indicates a hardened derivation step.

PUBLIC-KEY CRYPTOGRAPHY

secp256k1

secp256k1 defines the elliptic curve used to calculate a public key from a private key through scalar multiplication:

Q = kG

The resulting public key is a curve point with coordinates X and Y. The same key pair can also be used for ECDSA digital signatures.

CRYPTOGRAPHIC HASHING

Keccak-256

Keccak-256 is a cryptographic hash function producing a 256-bit digest.

Ethereum hashes the 64-byte public key coordinates, excluding the initial 04 prefix of the uncompressed key. The last 20 bytes form the address.

ERROR DETECTION

EIP-55

EIP-55 defines a mixed-case checksum representation of Ethereum addresses.

It hashes the lowercase hexadecimal address as text and uses the hash to determine letter capitalization. The underlying 20-byte address remains unchanged.

Different Cryptographic Operations

Although these technologies appear in the same wallet pipeline, they perform different operations and provide different properties.

Key Generation

Creates new secret material from cryptographically secure randomness. Our demonstration starts from a fixed public test mnemonic instead.

Key Derivation

Deterministically produces seed or key material from existing inputs. BIP-39, BIP-32 and BIP-44 participate in different parts of this process.

Public-Key Computation

Calculates a public key from a private scalar using elliptic-curve multiplication. It is the same mathematical operation explored in Homework 1.

Hashing

Converts data into a fixed-length digest. Keccak-256 is used to calculate Ethereum addresses and EIP-55 checksums.

Digital Signing

Uses a private key to authenticate data through a digital signature, such as ECDSA. Signing is not required to generate an Ethereum address.

Encoding

Represents information in another form, such as mnemonic words or hexadecimal characters. Encoding is not encryption and does not provide secrecy.

Checksum

Adds information for detecting accidental errors. BIP-39 uses checksum bits in mnemonic generation, while EIP-55 uses address capitalization.

SHA-2, Keccak-256 and SHA3-256

SHA-512 belongs to the SHA-2 family and is used within HMAC and PBKDF2 in our seed and key derivation steps.

Keccak-256 is used by Ethereum for address generation. Although related to SHA3-256, the two functions use different domain separation and padding conventions, producing different digests for the same input.

Therefore, SHA3-256 cannot simply replace Keccak-256 in Ethereum address derivation.

04 / HISTORICAL CONTEXT

Cryptographic Timeline

The evolution of public-key cryptography, hash functions and wallet standards.

Historical Evolution

Modern Ethereum wallets combine cryptographic techniques developed over several decades. This timeline highlights the most important milestones behind the technologies used in our experiment.

  1. 1977
    PUBLIC-KEY CRYPTOGRAPHY

    RSA

    Rivest, Shamir and Adleman introduce RSA, a major milestone in public-key cryptography. It demonstrates how public and private keys can support encryption and digital signatures.

  2. 2001
    CRYPTOGRAPHIC HASHING

    SHA-2 Family

    The SHA-2 family introduces hash functions such as SHA-256 and SHA-512. SHA-512 is later used within HMAC and PBKDF2 for wallet seed and key derivation.

  3. 2012
    DETERMINISTIC WALLETS

    BIP-32

    BIP-32 introduces hierarchical deterministic wallets, allowing many related keys to be derived from a single master seed.

  4. 2013
    MNEMONIC PHRASES

    BIP-39

    BIP-39 defines mnemonic sentences that represent entropy in a human-readable form and specifies how to derive a binary seed using PBKDF2-HMAC-SHA512.

  5. 2014
    WALLET ORGANIZATION

    BIP-44

    BIP-44 standardizes a multi-account hierarchy for deterministic wallets, including purpose, coin type, account, change and address index.

  6. 2015
    HASH STANDARDIZATION

    SHA-3 Standard

    NIST standardizes SHA-3 in FIPS 202, based on the Keccak design selected in 2012. Ethereum uses Keccak-256, which differs from standardized SHA3-256 in its padding conventions.

  7. 2016
    ETHEREUM ADDRESS CHECKSUM

    EIP-55

    EIP-55 introduces mixed-case checksum encoding for Ethereum addresses, improving the detection of accidental typing errors without changing the underlying address.

Historical note: RSA is included as an early public-key cryptography milestone, not as part of Ethereum wallet derivation. SHA-2 appeared in 2001 and was standardized by NIST in FIPS 180-2 in 2002.

05 / STATISTICAL EXPLORATION

Statistical Properties

Exploring the avalanche behavior and statistical properties of Keccak-256.

Keccak-256 Avalanche Experiment

A desirable property of cryptographic hash functions is that a small change in the input causes substantial changes in the resulting digest.

This experiment performs 64 deterministic trials. In each trial, exactly one input bit is flipped before computing Keccak-256. The modified digest is compared with the original digest.

Hamming Distance = Number of differing bits

Bit Balance — Percentage of 1 bits · Expected ≈ 50%
Empirical Binary Entropy — Bits per bit · Maximum = 1

Distribution of Hamming Distances

The histogram groups the 64 experiments according to how many of the 256 hash bits changed. For an ideal avalanche behavior, the results should be concentrated around 128 changed bits.

Run the experiment to display the distribution.

The experiment modifies raw hash inputs. Modified inputs are not guaranteed to be valid secp256k1 public keys. Their 160-bit hash suffixes are not independently generated Ethereum wallet addresses.

Interpreting the Results

If Keccak-256 exhibits the expected avalanche behavior, changing one input bit should change approximately half of the output bits on average.

A balanced number of zero and one bits also produces an empirical binary Shannon entropy close to 1 bit per bit.

However, this entropy measures only the observed proportion of zeros and ones. It does not measure private-key entropy or establish the unpredictability of individual hash outputs.

Because the experiment uses only 64 related inputs, its results are descriptive. They illustrate expected statistical behavior but cannot prove cryptographic security or collision resistance.

06 / DISCUSSION

Discussion and Conclusions

Interpreting the cryptographic pipeline, experimental results and security implications.

Understanding the Complete Pipeline

The experiment demonstrates how a single mnemonic phrase can deterministically produce an Ethereum address through multiple cryptographic operations.

BIP-39 transforms the mnemonic and passphrase into a 512-bit seed through PBKDF2-HMAC-SHA512. BIP-32 then derives a master private key and chain code. BIP-44 specifies the hierarchical path used to select the first Ethereum account's private key.

The public key is calculated using elliptic-curve scalar multiplication on secp256k1. Keccak-256 hashes its 64-byte coordinate representation, and the final 20 bytes become the Ethereum address.

Finally, EIP-55 determines a mixed-case checksum representation of the address. This final operation does not create another address or change its bytes.

Statistical Findings

The avalanche experiment performed 64 deterministic one-bit input modifications and compared the resulting Keccak-256 digests against the original digest.

For the selected test vector, the average Hamming distance was 127.63 out of 256 bits. This is close to the ideal reference value of 128 changed bits.

Considering only the last 160 bits of each digest, the average Hamming distance was 79.69 out of 160 bits, also close to the theoretical reference of 80.

Across the 64 modified digests, 49.19% of output bits were equal to 1. The corresponding empirical binary Shannon entropy was approximately 0.9998 bits per bit.

These results are consistent with the expected avalanche behavior and approximately balanced output bits. The histogram also shows that most Hamming distances are concentrated around half the digest length.

Security Implications and Limitations

Deterministic Derivation

The same mnemonic, passphrase and derivation path produce the same keys and address. This is useful for wallet recovery, but it also means that anyone who knows the recovery secrets can reproduce the wallet's private keys.

Hashing and Digital Signatures

Hashing is used to derive the address representation, whereas digital signatures are used to authenticate transactions. Ethereum's traditional externally owned accounts use ECDSA signatures based on secp256k1. No digital signature is needed to generate an address.

Hash Function Differences

SHA-512 is used within the HMAC and PBKDF2 constructions in the derivation process. Ethereum address generation instead requires Keccak-256.

Although Keccak-256 and standardized SHA3-256 are closely related, their domain separation and padding conventions differ. They cannot be substituted for one another in this pipeline.

Limits of the Statistical Analysis

The experiment evaluates only 64 related hash inputs derived from one public-key byte sequence. The observed bit balance and Hamming distances describe this particular sample and do not prove collision resistance or other security guarantees.

The reported binary entropy measures the empirical frequency of zero and one bits in the sampled digests. It must not be interpreted as the entropy of a wallet's private key or as a proof of hash unpredictability.

Furthermore, a modified input to Keccak-256 does not necessarily represent a valid elliptic-curve public key. The statistical experiment therefore analyzes the hash function, rather than generating independent Ethereum wallets.

Final Conclusions

This homework illustrates how Ethereum wallet derivation combines standards for mnemonic representation, deterministic key derivation, elliptic-curve public-key computation, hashing and checksum encoding.

The interactive pipeline successfully derives an Ethereum address from a publicly known BIP-39 test vector, with intermediate values checked against reference results.

The statistical experiment provides a quantitative illustration of the avalanche behavior of Keccak-256. Its results are compatible with the expected diffusion properties of a cryptographic hash function, while remaining limited to a small, deterministic sample.

Together, the practical demonstration and statistical analysis highlight an essential principle of applied cryptography: secure systems combine different primitives, each designed for a specific task.
