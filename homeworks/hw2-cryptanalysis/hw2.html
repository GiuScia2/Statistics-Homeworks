Encryption & Cryptanalysis

Elliptic-Curve Encryption and Caesar Cipher

An interactive comparison of two encryption schemes, including statistical cryptanalysis, key recovery and the security implications of restricted key spaces.

01 / INTRODUCTION

Understanding Encryption

Exploring how different cryptographic schemes protect messages and how their weaknesses can be exploited.

Introduction and Objectives

This homework compares a simplified elliptic-curve encryption scheme based on secp256k1 with the classical Caesar cipher.

Both schemes will encrypt and decrypt the same message, allowing a direct comparison of their algorithms, key spaces and security properties.

The project also investigates two attacks: statistical key recovery against the Caesar cipher and exhaustive private-key search against an intentionally weakened elliptic-curve scheme.

02 / ELLIPTIC-CURVE ENCRYPTION

Encrypting with secp256k1

Encrypt and decrypt a message using a simplified ECIES-inspired scheme.

ECC Encryption and Decryption

The receiver selects a private key d and computes the public key Q = dG. The sender chooses a fresh random value r, publishes R = rG, and computes the shared point S = rQ. The receiver recovers the same point using S = dR.

Q = dG   |   R = rG   |   rQ = dR

A SHA-256-based keystream is derived from the shared point and R, then XORed with the UTF-8 message. This is an educational construction, not a secure or authenticated ECIES implementation.

Intentionally restricted for the key-recovery attack.

03 / CAESAR CIPHER

Classical Encryption

Encrypt and decrypt the same message using a classical substitution cipher.

Caesar Encryption and Decryption

The Caesar cipher replaces each alphabetic character with another letter shifted by a fixed number of positions.

E(x) = (x + k) mod 26
D(y) = (y - k) mod 26

The key space contains 26 possible shifts, from 0 to 25. Non-alphabetic characters are preserved, and letter case is maintained.

04 / CRYPTOGRAPHIC COMPARISON

Comparing the Two Schemes

A comparison of encryption, decryption, key spaces and statistical characteristics.

ECC vs. Caesar Cipher

Both schemes transform a plaintext into a ciphertext and allow an authorized receiver to recover the original message. However, their cryptographic principles and security properties differ substantially.

Property ECC Toy Scheme Caesar Cipher
Cryptographic model Asymmetric encryption using elliptic-curve key agreement. Symmetric substitution cipher.
Encryption Uses the receiver's public key, an ephemeral scalar and a derived XOR keystream. Shifts each alphabetic character by a fixed number of positions.
Decryption Uses the receiver's private key to reconstruct the shared secret. Reverses the shift using the same key.
Key types Private key d, public key Q = dG, and fresh ephemeral scalar r. One secret shift key k.
Key space in this experiment 4,096 possible receiver private keys. 26 possible shifts, including the identity shift k = 0.
Full-size key space Approximately 2^256 possible private scalars for secp256k1. Only 26 possible shifts.
Repeated encryption A fresh ephemeral scalar normally produces a different ciphertext. The same message and key always produce the same ciphertext.
Statistical properties The SHA-256-derived keystream masks direct plaintext letter frequencies. Letter frequencies are preserved but shifted within the alphabet.
Attack in this homework Exhaustive search over the restricted private-key interval. Letter-frequency analysis and exhaustive evaluation of 26 shifts.
Authentication Not provided by this educational construction. Not provided.
Security observation

The underlying secp256k1 curve supports a very large private-key space, but this experiment deliberately limits the receiver's private key to 4,096 possibilities. This restriction makes exhaustive recovery feasible.

The ECC demonstration is not a complete, authenticated ECIES implementation and must not be used to protect real data.

05 / STATISTICAL CRYPTANALYSIS

Recovering the Caesar Key

Recover a Caesar cipher key using English letter-frequency analysis and evaluate the effect of ciphertext length.

Automatic Key Recovery

The attack evaluates all 26 possible Caesar keys. For each candidate, it compares the recovered letter distribution with a reference English distribution using the chi-squared statistic. The lowest-scoring candidate is selected.

chi² = Σ (Observed - Expected)² / Expected

07 / DISCUSSION AND CONCLUSIONS

Security and Statistical Insights

Comparing the effectiveness, assumptions and limitations of the cryptanalytic attacks.

Comparison of the Two Attacks

The experiments illustrate two different cryptanalytic strategies: exploiting linguistic statistics and searching a restricted private-key space.

Property Caesar Cryptanalysis ECC Key Recovery
Attack type Statistical frequency analysis, evaluating all possible shifts. Exhaustive private-key search using the public key.
Information required Ciphertext and a reference language distribution. Receiver's public key and knowledge of the restricted private-key interval.
Search space 26 possible shift values. 4,096 possible private keys in the toy experiment.
Source of weakness Small key space and preservation of plaintext letter frequencies. Deliberately restricted private-key space.
Influence of message length Longer English ciphertexts generally provide more reliable frequency estimates. Public-key search does not depend on ciphertext length.
Recovery guarantee The best statistical guess is not guaranteed to be correct, especially for short texts. A matching key is guaranteed to be found if it lies in the fully searched interval.
Real-world implications Caesar encryption remains weak regardless of key selection. Properly generated full-size secp256k1 keys resist this exhaustive-search approach.

Effectiveness and Limitations

Caesar Cipher

Letter-frequency analysis exploits the statistical structure of natural language. Its effectiveness generally improves with the amount of representative ciphertext.

Short texts, unusual vocabulary, non-English messages and unsuitable reference corpora may lead to incorrect key rankings.

Exhaustively testing all 26 shifts is also practical, although identifying meaningful plaintext may require additional linguistic information.

Elliptic-Curve Scheme

The restricted private-key interval makes it practical to reconstruct the receiver's secret key from its public key.

This weakness is introduced by the experimental key-generation constraint, not by the mathematical definition of secp256k1 itself.

Separately, the toy encryption construction lacks ciphertext authentication and is vulnerable to undetected modifications. It must not be treated as a secure ECIES implementation.

Final Conclusion

The Caesar cipher is vulnerable because its limited key space and deterministic substitution preserve linguistic patterns. Statistical cryptanalysis exploits these patterns, particularly when sufficient ciphertext is available.

The educational elliptic-curve scheme demonstrates a different weakness: restricting private keys to a small interval makes exhaustive recovery computationally practical even when using a well-known cryptographic curve.

Overall, these experiments show that cryptographic security depends not only on the underlying mathematical algorithm, but also on key generation, implementation choices, available information and the size of the search space.
